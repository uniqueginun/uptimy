# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project overview

Uptime is a Laravel + Inertia (React) starter-kit-based application for monitoring website availability. Authenticated users register **sites** (a URL) and attach one or more **endpoints** (a URI + check interval) to each site to be monitored. The endpoint-checking/scheduling logic itself has not been built yet — `Endpoint` currently only stores `uri` and `interval`; fields like `last_check`, `last_status`, and `uptime` are already exposed by `EndpointResource` but have no backing columns or job/command that populates them.

## Commands

Backend (PHP 8.3+, Laravel 13, Pest):
- `composer dev` — run the full local dev stack (`php artisan dev`, which runs the server, queue listener, and Vite together).
- `composer test` — the full check used in CI-equivalent local runs: clears config, then runs `lint:check`, `types:check`, and `php artisan test`.
- `composer lint` / `composer lint:check` — format (or check formatting) with Pint (`vendor/bin/pint --parallel`).
- `composer types:check` — run Larastan/PHPStan (`phpstan.neon`, level 7, no relaxations).
- `php artisan test --compact` or `vendor/bin/pest --compact` — run the full Pest suite. Pass a file path or `--filter=testName` to scope to one test; rerun the specific test after each change.
- `composer ci:check` — everything CI runs: `npm run check`, `npm run types:check`, and the PHP test suite.

Frontend (React 19 + TypeScript, Inertia v3, Tailwind v4, built with `vite-plus`):
- `npm run dev` — Vite dev server.
- `npm run build` / `npm run build:ssr` — production build (SSR build also builds the SSR bundle).
- `npm run check` / `npm run check:fix` — lint (ESLint via `vite-plus`, type-aware, warnings denied) and auto-fix.
- `npm run types:check` — `tsc --noEmit`.

Frontend build artifacts (`resources/js/actions/**`, `resources/js/routes/**`, `resources/js/wayfinder/**`) are generated by the Wayfinder Vite plugin from PHP routes/controllers — don't hand-edit them; they regenerate on `npm run dev`/`build`. If a route/controller signature changes and the UI doesn't pick it up, that's the fix, not the frontend code.

## Architecture

**Backend**
- Routes: `routes/web.php` (site/endpoint CRUD + dashboard/home) and `routes/settings.php` (profile/security/appearance), both behind `auth`(+`verified`) middleware groups. `routes/settings.php` is `require`d from `web.php`.
- Site/endpoint routes are nested under a `{domain}` prefix (`Route::prefix('{domain}')->as('sites.')`), not a numeric site ID — controllers resolve the owning `Site` via the `byDomain` local scope on `Site` (a `REGEXP` match against the stored `url`), e.g. `Site::byDomain($domain)->firstOrFail()`. Site ownership is scoped through `$request->user()->sites()` where relevant.
- `Site` has an appended `domain` accessor (derived from `url` via `parse_url`) — treat `domain` as the natural identifier for routing/lookups in this app, not `id`.
- Auth is handled entirely by **Laravel Fortify** (`app/Actions/Fortify/*`, `app/Providers/FortifyServiceProvider.php`, `config/fortify.php`). Only `registration` and `resetPasswords` features are enabled in `config/fortify.php` — two-factor auth UI/request classes exist (`SecurityController`, `TwoFactorAuthenticationRequest`) but the corresponding Fortify feature is not turned on.
- Controllers return Inertia responses directly (`Inertia::render(...)`) or use `Route::inertia(...)` for pages with no controller logic (e.g. `dashboard`, `welcome`, `settings/appearance`). Flash messages for toasts use `Inertia::flash('toast', ['type' => ..., 'message' => ...])`, consumed client-side by `use-flash-toast.ts`.
- API Resources (`app/Http/Resources/SiteResource.php`, `EndpointResource.php`) shape all data sent to the frontend; `SiteResource` conditionally includes `endpoints` via `whenLoaded`.
- `HandleInertiaRequests` shares `auth.user`, `name` (app name), and `sidebarOpen` (from a cookie) on every Inertia response.

**Frontend**
- Inertia pages live in `resources/js/pages/**`, mapped 1:1 to `Inertia::render()` calls (e.g. `sites/index`, `sites/show`, `settings/security`). Layouts are in `resources/js/layouts/**` (app shell/sidebar/header variants, auth variants, settings layout).
- Reusable UI primitives from shadcn/ui live in `resources/js/components/ui/**` — check there before adding a new primitive; this directory is excluded from lint/format rewriting (see `vite.config.ts`).
- Route/controller calls from the frontend go through generated Wayfinder helpers in `resources/js/actions/**` (controller-method calls) and `resources/js/routes/**` (named routes) — use these instead of hardcoding URLs or route names.
- Path alias `@/*` maps to `resources/js/*` (see `tsconfig.json`).

**Testing**
- Pest, with `RefreshDatabase` applied to all `Feature` tests via `tests/Pest.php`. Only `Feature` tests are auto-bound to `TestCase`; there's no equivalent binding for `Unit`.
- Tests run against an in-memory SQLite DB (`phpunit.xml`); queue is `sync`, mail is `array`.
- `Tests\TestCase::skipUnlessFortifyHas($feature)` skips a test when a given Fortify feature isn't enabled in `config/fortify.php` — used by the auth test suites since only a subset of Fortify features are turned on.

# Inertia

- Inertia creates fully client-side rendered SPAs without modern SPA complexity, leveraging existing server-side patterns.
- Components live in `resources/js/pages` (unless specified in `vite.config.js`). Use `Inertia::render()` for server-side routing instead of Blade views.
- ALWAYS use `search-docs` tool for version-specific Inertia documentation and updated code examples.
- IMPORTANT: Activate `inertia-react-development` when working with Inertia client-side patterns.

# Inertia v3

- Use all Inertia features from v1, v2, and v3. Check the documentation before making changes to ensure the correct approach.
- New v3 features: standalone HTTP requests (`useHttp` hook), optimistic updates with automatic rollback, layout props (`useLayoutProps` hook), instant visits, simplified SSR via `@inertiajs/vite` plugin, custom exception handling for error pages.
- Carried over from v2: deferred props, infinite scroll, merging props, polling, prefetching, once props, flash data.
- When using deferred props, add an empty state with a pulsing or animated skeleton.
- Axios has been removed. Use the built-in XHR client with interceptors, or install Axios separately if needed.
- `Inertia::lazy()` / `LazyProp` has been removed. Use `Inertia::optional()` instead.
- Prop types (`Inertia::optional()`, `Inertia::defer()`, `Inertia::merge()`) work inside nested arrays with dot-notation paths.
- SSR works automatically in Vite dev mode with `@inertiajs/vite` - no separate Node.js server needed during development.
- Event renames: `invalid` is now `httpException`, `exception` is now `networkError`.
- `router.cancel()` replaced by `router.cancelAll()`.
- The `future` configuration namespace has been removed - all v2 future options are now always enabled.
